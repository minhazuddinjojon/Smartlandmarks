3. HOW IT WAS DIRECTED — THE ACTUAL DECISIONS
-------------------------------------------------------------------------------
The AI was not given a free hand. The following were specified or chosen and
then reviewed, and they are the decisions that shaped the result:

  a. Stack was mandated up front: Kotlin only, MVVM + Repository, Room,
     Retrofit, Coroutines, StateFlow, WorkManager, Material 3, Navigation
     Component, ViewBinding, Coil. No Java.

  b. Map provider: osmdroid was chosen over Google Maps, deliberately, so the
     project needs no API key or billing account and stays extract-and-run.

  c. A written architecture plan was produced and reviewed BEFORE any code was
     generated, covering the database design, the offline strategy, the
     WorkManager strategy, and the error-handling strategy.

  d. Two design calls were made at plan time and are load-bearing:
       - the visit history table and the offline visit queue are ONE table,
         because they are the same data at different lifecycle stages;
       - the sync worker posts queued visits BEFORE polling jobs within a
         single pass, so an offline visit can resolve fully in one run.

  e. The score colour ramp is stretched across the observed score range rather
     than a fixed scale, because scores vary per student key.


4. CORRECTIONS MADE DURING GENERATION
-------------------------------------------------------------------------------
The AI's first output was not accepted as-is. Issues caught and fixed:

  - A placeholder function (`fileContext`) that threw
    UnsupportedOperationException was generated inside the multipart upload
    path. Removed; MIME type is now derived from the file extension, which
    needs no Context.
  - MapView.setMinZoomLevel / setMaxZoomLevel were written as Kotlin property
    assignments. osmdroid's getter returns a primitive double while the setter
    takes a boxed Double, so no property is synthesised. Changed to explicit
    setter calls.
  - android.preference.PreferenceManager (deprecated since API 29) was used for
    osmdroid configuration. Replaced with getSharedPreferences.
  - A unit test asserted "0.81 km" for a distance of 812.35 m, which is wrong —
    that value formats as metres. Corrected.
  - Launcher icons were generated only as adaptive icons (API 26+), leaving
    API 24-25 without one. Unqualified mipmap fallbacks added.


5. VERIFICATION PERFORMED
-------------------------------------------------------------------------------
A static analysis script was written and run over the entire source tree,
checking: package/directory agreement, resolution of every R.* reference in
Kotlin, resolution of every resource reference in every XML file, agreement
between each fragment's ViewBinding usage and its layout, existence of every
class named in the manifest and nav graph, bottom-nav ids matching nav
destination ids, resolution of every intra-project import, XML well-formedness,
Kotlin brace balance, absence of TODO/placeholder markers, and confirmation
that all six API endpoints are both implemented and called.

It reports zero errors.

HOWEVER — and this is stated plainly — the project was generated in an
environment with no Android SDK and no access to the Google/Maven repositories.
`./gradlew assembleDebug` was never executed. The code has not been compiled or
run against the live API. Static analysis catches unresolved references and
structural mistakes; it does not catch type errors, KSP/Hilt generation
failures, or runtime behaviour.
